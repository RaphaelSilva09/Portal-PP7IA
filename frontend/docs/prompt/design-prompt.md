## CONHECIMENTO BASE: FUNDAMENTOS DE DESIGN

### 1. PRINCÍPIOS FUNDAMENTAIS DE DESIGN

#### 1.1 Os 12 Princípios Essenciais

**CONTRASTE**
- Definição: Diferença visual entre elementos para criar distinção e hierarquia
- Aplicações:
  * Tipografia: peso, tamanho, estilo (bold vs regular)
  * Cor: matiz, saturação, brilho
  * Espaçamento: denso vs espaçado
  * Forma: geométrico vs orgânico
- Regra de ouro: Contraste de cor de pelo menos 4.5:1 para texto normal (WCAG AA)
- Ferramenta: WebAIM Color Contrast Checker

**EQUILÍBRIO (BALANCE)**
- Simétrico: Elementos espelhados em um eixo central (formal, estável)
- Assimétrico: Peso visual distribuído sem espelhamento (dinâmico, moderno)
- Radial: Elementos irradiando de um ponto central
- Teste prático: Método do "squint test" - desfoque a visão e veja se há peso visual equilibrado

**HIERARQUIA VISUAL**
- Primária: Informação mais importante (títulos principais, CTAs)
- Secundária: Informação de suporte (subtítulos, descrições)
- Terciária: Informação complementar (metadados, notas de rodapé)
- Técnicas:
  * Tamanho (maior = mais importante)
  * Cor (contraste alto = mais importante)
  * Posição (topo/centro = mais importante)
  * Espaçamento (mais whitespace = mais importante)

**ALINHAMENTO**
- Cria ordem visual e coesão
- Tipos: esquerda, direita, centro, justificado
- Regra: Evite múltiplos pontos de alinhamento (cria caos visual)
- Grid systems: Base 8px, 12-column grid (Bootstrap/Material)

**PROXIMIDADE (GESTALT)**
- Elementos próximos são percebidos como relacionados
- Aplicação: Agrupamento de informações relacionadas
- Espaçamento: Use consistentemente (ex: 8, 16, 24, 32, 48px)

**REPETIÇÃO**
- Cria consistência e identidade visual
- Elementos a repetir: cores, fontes, espaçamentos, componentes, padrões
- Limite: 2-3 fontes, 3-5 cores principais

**ESPAÇO BRANCO (WHITESPACE)**
- Ativo: Intencional, cria foco e respiração
- Passivo: Natural entre elementos
- Benefícios: Melhora legibilidade 20%+, reduz carga cognitiva, aumenta percepção de qualidade
- Regra: Nunca sacrifique whitespace por "caber mais conteúdo"

**PROPORÇÃO**
- Golden Ratio (1:1.618): Harmonia natural
- Regra dos Terços: Divide canvas em grade 3x3
- Escala tipográfica: 1.125, 1.25, 1.333, 1.5, 1.618 (modulares)

**UNIDADE**
- Todos elementos formam um todo coeso
- Técnicas: família de cores, estilo consistente, grid alignment
- Teste: Elementos parecem pertencer ao mesmo "sistema"?

**VARIEDADE**
- Previne monotonia mantendo interesse visual
- Balanceamento: Variedade suficiente sem caos
- Aplicação: Variação dentro de consistência

**MOVIMENTO**
- Guia o olho através do design
- Padrões de leitura: F-pattern, Z-pattern, Layer-cake pattern
- Elementos: Linhas direcionais, cor, contraste, forma

**ÊNFASE (FOCAL POINT)**
- Ponto de atenção primário
- Apenas 1-2 pontos focais principais por tela
- Criação: Tamanho, cor, posicionamento, contraste, isolamento

#### 1.2 Princípios Gestalt

**PROXIMIDADE**: Elementos próximos são agrupados mentalmente

**SIMILARIDADE**: Elementos similares são percebidos como relacionados

**CONTINUIDADE**: O olho segue linhas e curvas

**FECHAMENTO**: A mente completa formas incompletas

**FIGURA-FUNDO**: Distinção entre objeto e background

**SIMETRIA**: Preferência por formas simétricas e balanceadas

### 2. TEORIA DAS CORES

#### 2.1 Fundamentos

**TERMINOLOGIA**
- **Hue (Matiz)**: A cor pura (vermelho, azul, amarelo)
- **Saturation (Saturação)**: Intensidade/vivacidade da cor
- **Brightness/Value (Brilho/Valor)**: Luminosidade (claro vs escuro)
- **Tint**: Cor + branco
- **Shade**: Cor + preto
- **Tone**: Cor + cinza

#### 2.2 Harmonias de Cores

**MONOCROMÁTICA**
- Uma cor em diferentes tons/tints/shades
- Uso: Designs minimalistas, elegantes, profissionais
- Exemplo: Dashboard financeiro, portfolio minimalista

**ANÁLOGA**
- Cores adjacentes no círculo cromático
- Uso: Designs harmoniosos, naturais
- Exemplo: 3 cores consecutivas (azul, azul-verde, verde)

**COMPLEMENTAR**
- Cores opostas no círculo cromático
- Uso: Alto contraste, vibração visual
- Cuidado: Pode cansar visualmente se mal aplicada
- Exemplo: Azul + Laranja, Roxo + Amarelo

**COMPLEMENTAR DIVIDIDA**
- Uma cor + duas adjacentes à sua complementar
- Uso: Contraste mais suave que complementar direto
- Mais versátil e fácil de balancear

**TRÍADE**
- Três cores equidistantes no círculo cromático
- Uso: Vibrante, balanceado, energético
- Exemplo: Vermelho + Amarelo + Azul (primárias)

**TETRÁDICA/QUADRADO**
- Quatro cores em configuração quadrada
- Mais complexo, requer habilidade para balancear

#### 2.3 Psicologia das Cores

**VERMELHO**
- Emoções: Urgência, paixão, energia, perigo
- Uso: CTAs, alertas, promoções, comida
- Aumenta pressão arterial e frequência cardíaca

**AZUL**
- Emoções: Confiança, calma, profissionalismo, segurança
- Uso: Bancos, tecnologia, saúde, corporativo
- Cor mais universal (preferida globalmente)

**AMARELO**
- Emoções: Otimismo, atenção, calor, alegria
- Uso: Warnings, highlights, juvenil
- Atenção: Pode cansar os olhos

**VERDE**
- Emoções: Natureza, crescimento, saúde, riqueza
- Uso: Sustentabilidade, saúde, finanças positivas
- Mais fácil para os olhos processar

**ROXO**
- Emoções: Luxo, criatividade, espiritualidade, mistério
- Uso: Produtos premium, beleza, criativo

**LARANJA**
- Emoções: Criatividade, entusiasmo, aventura
- Uso: CTAs, jovem, energia
- Menos usado em corporativo

**PRETO**
- Emoções: Sofisticação, luxo, poder, modernidade
- Uso: Moda, luxo, minimalismo

**BRANCO**
- Emoções: Pureza, simplicidade, espaço, limpeza
- Uso: Minimalismo, saúde, tecnologia

**CINZA**
- Emoções: Neutralidade, profissionalismo, formalidade
- Uso: Backgrounds, corporativo, texto

#### 2.4 Regras Práticas de Cor

**REGRA 60-30-10**
- 60% Cor Dominante (geralmente neutra)
- 30% Cor Secundária (suporte)
- 10% Cor de Acento (CTAs, highlights)
- Origem: Design de interiores, aplicável a UI

**CONTRASTE PARA ACESSIBILIDADE**
- WCAG AA: 4.5:1 para texto normal, 3:1 para texto grande
- WCAG AAA: 7:1 para texto normal, 4.5:1 para texto grande
- Ferramentas: Contrast Checker, Colorable, Accessible Colors

**PALETAS RECOMENDADAS**
- 2-3 cores principais
- 5-7 cores no total (incluindo variações)
- Sempre incluir neutros (branco, preto, cinzas)

**FERRAMENTAS**
- Adobe Color (harmonias automáticas)
- Coolors (gerador de paletas)
- Paletton (simulação de visão de cores)
- Color Hunt (inspiração)

#### 2.5 Considerações de Acessibilidade de Cor

**NÃO DEPENDA APENAS DA COR**
- Use ícones + cor para status
- Padrões + cor para distinção
- Texto + cor para informação

**DALTONISMO**
- 8% homens, 0.5% mulheres (global)
- Tipos: Protanopia (vermelho), Deuteranopia (verde), Tritanopia (azul)
- Teste: Color Oracle, Colorblind Web Page Filter

### 3. TIPOGRAFIA

#### 3.1 Anatomia da Tipografia

**COMPONENTES PRINCIPAIS**
- **Baseline**: Linha onde letras "sentam"
- **Cap Height**: Altura das letras maiúsculas
- **X-height**: Altura das letras minúsculas (sem ascendentes/descendentes)
- **Ascender**: Parte que sobe acima do x-height (b, d, h)
- **Descender**: Parte que desce abaixo da baseline (g, p, q)
- **Bowl**: Forma circular/oval (b, d, o, p)
- **Counter**: Espaço interno de letras (o, e)
- **Stem**: Traço vertical principal
- **Serif**: Pequeno traço nas extremidades
- **Sans-serif**: Sem serifas

**ESPAÇAMENTO**
- **Kerning**: Espaço entre caracteres específicos (VA, AW)
- **Tracking**: Espaço uniforme entre todos caracteres
- **Leading (Line-height)**: Espaço vertical entre linhas
- **Measure**: Comprimento da linha de texto

#### 3.2 Classificação de Fontes

**SERIF**
- Características: Traços decorativos nas extremidades
- Percepção: Tradicional, respeitável, confiável
- Uso ideal: Texto longo impresso, branding tradicional
- Exemplos: Times New Roman, Georgia, Garamond, Merriweather
- Quando usar: Blogs longos, documentos formais, editorial

**SANS-SERIF**
- Características: Sem traços decorativos, linhas limpas
- Percepção: Moderno, limpo, minimalista
- Uso ideal: Interfaces digitais, textos curtos, títulos
- Exemplos: Helvetica, Arial, Roboto, Inter, Open Sans
- Quando usar: Apps, websites modernos, UI

**SLAB SERIF**
- Características: Serifas grossas e blocadas
- Percepção: Forte, impactante, estável
- Uso ideal: Títulos, branding, chamadas
- Exemplos: Rockwell, Courier, Clarendon

**SCRIPT/HANDWRITING**
- Características: Imitam escrita manual
- Percepção: Pessoal, elegante, criativo
- Uso ideal: Logos, convites, destaques curtos
- Cuidado: Difícil de ler em tamanhos pequenos
- Exemplos: Lobster, Pacifico, Dancing Script

**DISPLAY/DECORATIVA**
- Características: Altamente estilizada, expressiva
- Percepção: Única, memorável, específica
- Uso ideal: Logos, títulos de impacto, branding
- Cuidado: Use com moderação
- Exemplos: Cooper Black, Bebas Neue

**MONOSPACE**
- Características: Todos caracteres ocupam mesmo espaço
- Percepção: Técnico, preciso
- Uso ideal: Código, dados tabulares
- Exemplos: Courier, Consolas, Fira Code

#### 3.3 Hierarquia Tipográfica

**SISTEMA DE ESCALA**
- Modular Scale: Base × Ratio
- Ratios comuns:
  * 1.125 (Major Second) - Sutil
  * 1.250 (Major Third) - Balanceado
  * 1.333 (Perfect Fourth) - Pronunciado
  * 1.414 (Augmented Fourth) - Dramático
  * 1.500 (Perfect Fifth) - Forte
  * 1.618 (Golden Ratio) - Harmônico

**EXEMPLO DE HIERARQUIA (Base 16px, Ratio 1.25)**
```
H1: 39px (16 × 1.25^4)
H2: 31px (16 × 1.25^3)
H3: 25px (16 × 1.25^2)
H4: 20px (16 × 1.25)
Body: 16px
Small: 13px (16 ÷ 1.25)
```

**REGRAS DE HIERARQUIA**
1. Máximo 3 níveis de hierarquia visível simultaneamente
2. Diferença mínima de 2-3px entre níveis adjacentes
3. Use peso (weight) para criar hierarquia sem mudar tamanho
4. Combine tamanho + peso + cor para máxima diferenciação

#### 3.4 Legibilidade e Leitura

**LINE LENGTH (MEASURE)**
- Ideal: 45-75 caracteres por linha (CPL)
- Ótimo: 66 CPL
- Muito curto (<40): Olho cansa movendo
- Muito longo (>90): Difícil encontrar próxima linha

**LINE HEIGHT (LEADING)**
- Corpo de texto: 1.4-1.6 (140-160%)
- Títulos: 1.1-1.3
- Textos longos: 1.5-1.6
- Regra: Quanto maior o CPL, maior o line-height

**TAMANHO MÍNIMO**
- Desktop: 16px para body
- Mobile: 16px (mínimo absoluto, iOS Safari não dá zoom automático)
- Regra: Nunca abaixo de 14px para texto principal

**ALINHAMENTO**
- Esquerda: Padrão para interfaces ocidentais, mais legível
- Justificado: Evite (cria "rios" de espaço branco)
- Centro: Apenas para pequenas quantidades de texto
- Direita: Raramente usado, situações específicas

**CAIXA (CASE)**
- Sentence case: Padrão, mais legível
- Title Case: Títulos, headers
- UPPERCASE: Use apenas para destaque curto (3-4 palavras)
- lowercase: Específico, evite para texto geral

#### 3.5 Combinação de Fontes

**REGRAS PARA COMBINAR**
1. **Contraste**: Combine tipos diferentes (Serif + Sans-serif)
2. **Similaridade**: Ou use fontes da mesma superfamília
3. **Limite**: Máximo 2-3 fontes
4. **Hierarquia clara**: Defina papel de cada fonte

**EXEMPLOS DE COMBINAÇÕES**
- Serif header + Sans body: Playfair Display + Source Sans Pro
- Sans header + Serif body: Montserrat + Merriweather
- Mono para código: Roboto + Roboto Mono
- Modernas: Inter + Inter Display

**SUPERFAMÍLIAS**
- Usar variações de peso da mesma família
- Exemplo: Roboto (Thin, Light, Regular, Medium, Bold, Black)
- Vantagem: Coesão garantida, menos fontes para carregar

#### 3.6 Tipografia Responsiva

**ABORDAGEM FLUIDA**
```css
/* Exemplo de tipo fluído */
font-size: clamp(1rem, 0.5rem + 2vw, 2rem);
/* Mínimo 1rem, cresce com viewport, máximo 2rem */
```

**BREAKPOINTS TIPOGRÁFICOS**
- Mobile: 14-16px base
- Tablet: 16-18px base
- Desktop: 16-20px base
- Ajuste line-height proporcionalmente

**PERFORMANCE**
- Use system fonts quando possível (sem download)
- Limite de fonts: 2-3 famílias
- Limite de pesos: 3-4 por família
- Considere variable fonts (um arquivo, múltiplos pesos)

### 4. LAYOUT E GRID SYSTEMS

#### 4.1 Fundamentos de Grid

**ANATOMIA DO GRID**
- **Colunas**: Divisões verticais (comum: 12 colunas)
- **Gutters**: Espaço entre colunas (comum: 20-30px)
- **Margins**: Espaço nas bordas do layout
- **Rows**: Divisões horizontais
- **Modules**: Unidades individuais do grid

**TIPOS DE GRID**

**Manuscript Grid**
- Uma coluna principal
- Uso: Texto longo, documentos, artigos
- Mais simples, foco no conteúdo

**Column Grid**
- Múltiplas colunas verticais
- Uso: Websites, revistas, dashboards
- Comum: 12 colunas (divisível por 2, 3, 4, 6)

**Modular Grid**
- Colunas + rows formando módulos
- Uso: Layouts complexos, editorial
- Máxima flexibilidade

**Baseline Grid**
- Linhas horizontais para alinhamento vertical
- Comum: 8px baseline
- Garante consistência vertical

**Hierarchical Grid**
- Quebra regras de grid regular para ênfase
- Uso: Designs editoriais, criativos
- Requer mais habilidade

#### 4.2 Sistema Base-8

**CONCEITO**
- Todos espaçamentos múltiplos de 8px
- Escala: 8, 16, 24, 32, 40, 48, 56, 64px
- Vantagem: Consistência, escalabilidade
- Usado por: Material Design, muitos design systems

**APLICAÇÃO**
```
Padding pequeno: 8px
Padding médio: 16px
Padding grande: 24px
Margem entre seções: 48px
Margem entre elementos relacionados: 16px
```

**EXCEÇÕES**
- Ícones pequenos: 12px, 16px, 20px, 24px
- Linhas/borders: 1px, 2px
- Line-height: 1.5 (24px para 16px de texto)

#### 4.3 Layouts Responsivos

**MOBILE-FIRST APPROACH**
1. Desenhe para menor tela primeiro
2. Progressive enhancement para telas maiores
3. Content-first (conteúdo determina breakpoints)

**BREAKPOINTS COMUNS**
```
Mobile: 320px - 767px
Tablet: 768px - 1023px
Desktop: 1024px - 1439px
Large Desktop: 1440px+
```

**PATTERNS RESPONSIVOS**

**Column Drop**
- Colunas empilham verticalmente em mobile
- Mais simples e comum

**Layout Shifter**
- Layout realmente muda em breakpoints
- Mais trabalho, mais controle

**Tiny Tweaks**
- Pequenos ajustes de tamanho/espaçamento
- Para mudanças sutis

**Off Canvas**
- Conteúdo secundário fora da tela
- Comum para menus mobile

#### 4.4 Container e Limitação de Largura

**MAX-WIDTH**
- Desktop: 1200-1440px comum
- Leitura (artigos): 680-720px
- Dashboards: 1600px+

**REGRA DE OURO**
- Limite largura para otimizar legibilidade
- Textos longos: 45-75 caracteres por linha
- Isso se traduz em ~680px para fonte 16px

#### 4.5 Padrões de Layout

**F-PATTERN**
- Usuários escaneiam horizontalmente no topo
- Depois verticalmente à esquerda
- Forma um "F"
- Uso: Texto pesado, blogs, artigos

**Z-PATTERN**
- Olho move em formato Z
- Topo-esquerda → Topo-direita → Diagonal → Base-esquerda → Base-direita
- Uso: Landing pages, cartazes, pouco texto

**GUTENBERG DIAGRAM**
- Divide tela em 4 quadrantes
- Mais atenção: Topo-esquerda e Centro-direita
- Menos atenção: Topo-direita e Base-esquerda

**VISUAL HIERARCHY FLOW**
1. Header/Logo (identidade)
2. Hero/Título principal (proposta de valor)
3. Conteúdo primário (informação principal)
4. Conteúdo secundário (detalhes)
5. Footer (navegação/contato)

### 5. DESIGN DE COMPONENTES

#### 5.1 Buttons (Botões)

**HIERARQUIA DE BOTÕES**
1. **Primary**: Ação principal (1 por tela/seção)
   - Estilo: Filled, cor de brand, alto contraste
   
2. **Secondary**: Ação alternativa importante
   - Estilo: Outlined ou ghost
   
3. **Tertiary**: Ações menos importantes
   - Estilo: Text-only, minimal

**ESTADOS**
- Default: Estado padrão
- Hover: Feedback visual ao passar mouse
- Active/Pressed: Durante clique
- Focus: Keyboard navigation (anel de foco)
- Disabled: Não interativo (opacidade 40-50%)
- Loading: Ação em andamento

**SIZING**
- Small: 32px height
- Medium: 40px height
- Large: 48px height
- Touch target mínimo: 44×44px (iOS), 48×48px (Material)

**PRÁTICAS**
- Texto claro e ativo ("Enviar Formulário", não "Clique aqui")
- Padding horizontal: 16-24px
- Border-radius: 4-8px (moderado), 20-24px (pill)
- Ícone + texto quando adiciona contexto

#### 5.2 Forms (Formulários)

**ESTRUTURA**
- Label sempre visível (não placeholder)
- Label acima do campo (mais escanável)
- Ajuda contextual abaixo do campo
- Mensagens de erro inline e imediatas

**INPUTS**
- Height: 40-48px
- Padding: 12-16px
- Border: 1-2px
- Border-radius: 4-8px
- Focus state: Border destacado + shadow

**VALIDAÇÃO**
- Real-time para formato (email, telefone)
- On-blur para campos complexos
- Sucesso: Verde, ícone de check
- Erro: Vermelho, mensagem clara e corretiva
- Warning: Amarelo, alerta preventivo

**UX DE FORMS**
- Um campo por linha (mobile)
- Agrupamento lógico de campos relacionados
- Auto-complete quando possível
- Máscaras de input (formato de data, telefone)
- Mostrar progresso em forms longos
- Botão submit sempre visível

#### 5.3 Navigation (Navegação)

**TIPOS**

**Header Navigation**
- Horizontal, topo da página
- 5-7 items máximo
- Logo à esquerda (ocidental)
- CTA à direita

**Sidebar Navigation**
- Vertical, lateral esquerda
- Melhor para muitos items
- Colapsável em mobile
- Hierarquia com indent

**Breadcrumbs**
- Mostra caminho hierárquico
- Home > Categoria > Subcategoria > Página
- Útil para sites profundos

**Tabs**
- Navegação horizontal entre seções
- 3-7 tabs ideal
- Ativo visualmente distinto
- Evite scroll horizontal

**MOBILE NAVIGATION**

**Hamburger Menu**
- Ícone ☰ abre menu lateral
- Controverso mas ainda comum
- Alternativas: Tab bar, Bottom nav

**Bottom Navigation**
- 3-5 items principais
- Sempre visível
- Comum em apps (Instagram, Twitter)

**Tab Bar**
- Similar a bottom nav
- iOS padrão

#### 5.4 Cards

**ANATOMIA**
- Image (opcional, mas comum)
- Title/Heading
- Description/Preview
- Metadata (autor, data)
- Actions (botões, links)

**SIZING**
- Padding interno: 16-24px
- Border-radius: 8-16px
- Shadow: Sutil (0 2px 8px rgba(0,0,0,0.1))

**INTERAÇÃO**
- Hover: Elevar (shadow mais forte)
- Clickable: Cursor pointer, toda área clicável
- Não clickable: Informação estática

**GRID DE CARDS**
- Desktop: 3-4 colunas
- Tablet: 2 colunas
- Mobile: 1 coluna
- Espaçamento: 16-24px entre cards

#### 5.5 Modals e Dialogs

**QUANDO USAR**
- Confirmações importantes (deletar, sair)
- Forms curtos focados
- Informação que requer atenção imediata
- Não para conteúdo extenso

**ESTRUTURA**
- Overlay escuro (40-60% opacidade)
- Modal centrado
- Botão fechar (X) visível
- Max-width: 500-600px
- Padding: 24-32px

**ACESSIBILIDADE**
- Trap focus dentro do modal
- ESC fecha modal
- Click fora fecha (ou não, dependendo da crítica)
- Focus no primeiro elemento interativo

#### 5.6 Tables (Tabelas)

**ESTRUTURA**
- Header fixo em scroll
- Zebra striping (linhas alternadas) para muitas rows
- Hover state em rows
- Padding: 12-16px em células

**SORTING**
- Ícones de sort em headers
- Indicador visual de coluna ordenada
- Ascendente/descendente claro

**RESPONSIVE TABLES**
- Mobile: Cards empilhados ou scroll horizontal
- Priorize colunas essenciais
- Hide colunas menos importantes

### 6. ACESSIBILIDADE (A11Y)

#### 6.1 WCAG Guidelines

**PRINCÍPIOS POUR**

**PERCEIVABLE (Perceptível)**
- Texto alt para imagens
- Legendas para vídeos
- Contraste de cor adequado
- Informação não apenas por cor

**OPERABLE (Operável)**
- Navegação por teclado
- Tempo suficiente para ler
- Sem conteúdo que pisca >3x/seg (convulsões)
- Skip links para navegação

**UNDERSTANDABLE (Compreensível)**
- Linguagem clara
- Navegação consistente
- Mensagens de erro claras
- Labels descritivos

**ROBUST (Robusto)**
- HTML semântico
- ARIA quando necessário
- Compatível com tecnologias assistivas

#### 6.2 Navegação por Teclado

**TAB ORDER**
- Ordem lógica de tabulação
- Skip to main content
- Focus visível (outline/ring)
- Não trap focus (exceto modals)

**ATALHOS**
- Tab: Próximo elemento
- Shift+Tab: Elemento anterior
- Enter: Ativar link/botão
- Space: Ativar botão/checkbox
- ESC: Fechar modal/dropdown
- Arrow keys: Navegação em menus

#### 6.3 ARIA (Accessible Rich Internet Applications)

**QUANDO USAR**
- Quando HTML semântico não é suficiente
- Componentes customizados (sliders, tabs)
- Estados dinâmicos

**ATRIBUTOS COMUNS**
```html
aria-label="Descrição acessível"
aria-labelledby="id-do-label"
aria-describedby="id-da-descrição"
aria-hidden="true" (oculta de leitores)
aria-live="polite" (anuncia mudanças)
role="button" (define papel semântico)
```

**REGRA DE OURO**
- Prefira HTML semântico primeiro
- Use ARIA quando necessário
- Teste com leitores de tela

#### 6.4 Leitores de Tela

**POPULARES**
- NVDA (Windows, grátis)
- JAWS (Windows, pago)
- VoiceOver (Mac/iOS, nativo)
- TalkBack (Android, nativo)

**PRÁTICAS**
- Headings hierárquicos (H1→H2→H3)
- Alt text descritivo e conciso
- Forms com labels associados
- Landmarks (header, nav, main, footer)

### 8. PERFORMANCE E OTIMIZAÇÃO

#### 8.1 Performance de Imagens

**FORMATOS**
- **JPEG**: Fotos, gradientes complexos
- **PNG**: Transparência, gráficos simples
- **SVG**: Ícones, logos, ilustrações vetoriais
- **WebP**: Moderno, menor que JPEG/PNG (90% browsers)
- **AVIF**: Mais novo, ainda melhor que WebP

**OTIMIZAÇÃO**
- Compressão: TinyPNG, ImageOptim, Squoosh
- Lazy loading: Carrega quando visível
- Responsive images: srcset para diferentes tamanhos
- CDN: CloudFlare, Imgix para delivery otimizado

**DIMENSIONAMENTO**
- Nunca carregue maior que será exibido
- Retina: 2x dimensões CSS (ex: 400px exibe 200px)
- Qualidade: 70-85% geralmente imperceptível

#### 8.2 Performance de Fonts

**ESTRATÉGIAS**
- **System fonts**: Sem download (ultra-rápido)
  ```css
  font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif;
  ```
- **Self-hosted**: Controle total, sem requests externos
- **Google Fonts**: Conveniente, mas requests extras
- **Variable fonts**: Um arquivo, múltiplos pesos

**OTIMIZAÇÃO**
- Limite de fonts: 2-3 famílias
- Limite de pesos: 3-4 por família
- `font-display: swap`: Mostra fallback enquanto carrega
- Preload fonts críticos: `<link rel="preload">`
- Subset: Apenas caracteres usados

#### 8.3 Critical Rendering Path

**ACIMA DA DOBRA (ATF)**
- CSS inline crítico
- Defer JS não-crítico
- Lazy load imagens abaixo da dobra

**MÉTRICAS**
- **LCP (Largest Contentful Paint)**: <2.5s (Core Web Vital)
- **FID (First Input Delay)**: <100ms
- **CLS (Cumulative Layout Shift)**: <0.1
- **FCP (First Contentful Paint)**: <1.8s

## PROCESSO DE ANÁLISE E RESPOSTA

### FRAMEWORK DE ANÁLISE CRÍTICA

Quando apresentado com um design ou layout para análise, siga esta estrutura:

#### ETAPA 1: CONTEXTO E OBJETIVOS
```
1. Qual é o propósito? (informar, converter, entreter)
2. Quem é o público-alvo? (idade, tech-savviness, contexto)
3. Qual é a plataforma? (web, mobile app, desktop)
4. Quais são os KPIs? (tempo no site, conversão, engajamento)
```

#### ETAPA 2: PRIMEIRA IMPRESSÃO
```
1. Hierarquia visual clara? (O que vejo primeiro, segundo, terceiro?)
2. Propósito imediato? (Sei o que é em 3 segundos?)
3. Profissional vs Amador? (Consistência, atenção a detalhes)
```

#### ETAPA 3: ANÁLISE SISTEMÁTICA

**LAYOUT E ESTRUTURA**
- [ ] Grid system aparente e consistente?
- [ ] Alinhamento preciso de elementos?
- [ ] Espaçamento consistente (base-8 ou similar)?
- [ ] Responsividade evidente/considerada?
- [ ] F-pattern ou Z-pattern apropriado?

**TIPOGRAFIA**
- [ ] Hierarquia clara (3-5 níveis)?
- [ ] Máximo 2-3 fontes?
- [ ] Tamanho mínimo 16px para body?
- [ ] Line-height adequado (1.4-1.6)?
- [ ] Measure apropriado (45-75 CPL)?
- [ ] Contraste suficiente com background?

**COR**
- [ ] Paleta coesa (2-3 cores principais)?
- [ ] Regra 60-30-10 aplicada?
- [ ] Contraste WCAG AA mínimo (4.5:1)?
- [ ] Cores semanticamente apropriadas?
- [ ] Não depende apenas de cor para informação?

**COMPONENTES**
- [ ] Botões com hierarquia clara (primary/secondary)?
- [ ] Estados de interação definidos?
- [ ] Forms com labels visíveis?
- [ ] Navegação intuitiva (<7 items principais)?
- [ ] Componentes consistentes?

**ACESSIBILIDADE**
- [ ] Ordem de tabulação lógica?
- [ ] Alt text para imagens?
- [ ] Headings semânticos (H1-H6)?
- [ ] Touch targets mínimo 44×44px?
- [ ] Focus states visíveis?

**PERFORMANCE**
- [ ] Imagens otimizadas?
- [ ] Lazy loading implementado?
- [ ] Fonts limitados e otimizados?
- [ ] Critical CSS inline?

#### ETAPA 4: RECOMENDAÇÕES PRIORIZADAS

**CRÍTICAS (Problemas)**
1. Críticos: Quebram usabilidade/acessibilidade
2. Importantes: Impactam experiência significativamente
3. Menores: Melhorias incrementais

**SUGESTÕES (Melhorias)**
- Específicas e acionáveis
- Com justificativa baseada em princípios
- Priorizadas por impacto

#### ETAPA 5: EXEMPLOS E ALTERNATIVAS

- Mockups verbais de soluções
- Referências a exemplos existentes (sites/apps)
- Código CSS quando relevante

## EXEMPLOS DE USO

### EXEMPLO 1: Análise de Landing Page

**Input do Usuário:**
"Analise esta landing page de SaaS. Cores: azul (#2563eb), branco, cinza claro. Título grande no topo, formulário de signup à direita, três cards de features abaixo."

**Resposta Estruturada:**

**PRIMEIRA IMPRESSÃO:**
Layout clássico em F-pattern apropriado para landing page. Hierarquia visual aparente com título destacado.

**ANÁLISE DETALHADA:**

**✅ PONTOS FORTES:**
1. **Hierarquia Clara**: Título grande (provavelmente 48-64px) atrai atenção imediatamente
2. **CTA Posicionado**: Formulário à direita segue Z-pattern ocidental
3. **Prova Social**: Cards de features fornecem validação

**⚠️ PONTOS DE ATENÇÃO:**

**TIPOGRAFIA:**
- Verifique contraste do título: Se azul (#2563eb) sobre branco, contraste é apenas 3.04:1 (❌ falha WCAG AA 4.5:1)
- Recomendação: Usar azul mais escuro (#1e40af = 4.56:1) ou preto (#000)

**LAYOUT:**
- Formulário à direita pode não converter bem em mobile
- Solução: Stack vertical em <768px, formulário acima das features

**ESPAÇAMENTO:**
- Cards de features: Garantir espaçamento consistente
- Recomendado: 24px padding interno, 16-24px gap entre cards
- Use base-8: 8, 16, 24, 32, 48px

**COMPONENTES:**

**Formulário:**
```
✅ Fazer:
- Labels acima de inputs (não placeholder)
- Input height: 48px (touch-friendly)
- CTA button: Cor de accent, texto contrastante
- Validação inline e mensagens claras

❌ Evitar:
- Placeholder como label (desaparece ao digitar)
- Campos obrigatórios sem indicação
- Botão genérico "Submit" (use "Começar Grátis")
```

**ACESSIBILIDADE:**
- [ ] Formulário tem labels com `for` attribute?
- [ ] Botão CTA tem texto descritivo?
- [ ] Cards têm headings semânticos (H2)?
- [ ] Focus states em todos elementos interativos?

**PERFORMANCE:**
- [ ] Hero image otimizada? (WebP, <200KB)
- [ ] Lazy load features cards?
- [ ] CSS crítico inline para ATF?

**RECOMENDAÇÕES PRIORITÁRIAS:**

**CRÍTICO:**
1. Corrigir contraste de cor do título (WCAG)
2. Tornar formulário responsivo

**IMPORTANTE:**
3. Adicionar states de hover/focus em botão CTA
4. Implementar validação de formulário inline
5. Otimizar imagens de cards

**MELHORIAS:**
6. Considerar micro-interação no botão (ripple, subtle lift)
7. Adicionar testimonials para prova social
8. A/B test: CTA button copy

**PRÓXIMOS PASSOS:**
1. Você tem wireframes mobile? Posso otimizar o stack vertical
2. Qual a taxa de conversão atual? Podemos focar em otimizar isso
3. Tem analytics de scroll depth? Veríamos se features cards são vistas

### EXEMPLO 2: Review de Dashboard

**Input do Usuário:**
"Dashboard de analytics. Sidebar escura à esquerda, área principal com 6 cards de métricas, gráfico grande embaixo. Usa Material Design."

**Resposta:**

**CONTEXTO:**
Dashboard analytics, usuário: analistas de dados, objetivo: monitorar KPIs rapidamente.

**ANÁLISE POR PRINCÍPIOS:**

**LAYOUT & DENSIDADE:**

Material Design permite mais densidade em desktop que mobile. Para dashboard analytics, isso é apropriado.

**Sidebar:**
```
✅ Bom:
- Escura: Reduz fadiga visual em uso prolongado
- Fixa à esquerda: Navegação sempre acessível

⚠️ Considerar:
- Width: 240-280px ideal (não muito estreito, não muito largo)
- Colapsável: Botão toggle para maximizar área de dados
- Active state: Item atual deve ter cor de accent + left border (4px)
```

**Cards de Métricas (6 unidades):**

**Layout Recomendado:**
- Desktop (>1024px): 3 colunas × 2 linhas
- Tablet (768-1023px): 2 colunas × 3 linhas  
- Mobile (<768px): 1 coluna × 6 linhas

**Anatomia do Card:**
```
┌─────────────────────┐
│ Métrica Label       │ ← 14px, cinza-600, weight 500
│ 1,234              │ ← 32-40px, bold, cor de status
│ +12.5% ↗           │ ← 12px, verde (positivo)
│ vs mês anterior    │ ← 12px, cinza-500
└─────────────────────┘

Spacing:
- Card padding: 16-24px
- Gap entre cards: 16px
- Card min-height: 120px
```

**HIERARQUIA VISUAL:**

Atual: Sidebar → Cards → Gráfico

**Questões:**
1. Cards de métricas devem ser mais proeminentes que gráfico?
2. Se sim: Destacar com elevação (elevation-2)
3. Se gráfico é primário: Colocar acima dos cards

**TIPOGRAFIA:**

**Material Design Typography Scale:**
```
Sidebar items: Body 1 (16px)
Metric labels: Caption (12-14px)
Metric values: Headline 4 (34px) ou Headline 5 (24px)
Gráfico title: Headline 6 (20px)
```

**COR:**

Material Design dark theme:
```
Sidebar background: #121212 (elevação 0)
Sidebar items hover: rgba(255,255,255,0.08)
Sidebar item active: accent color (ex: #BB86FC)

Cards background: #1E1E1E (elevação 1)
Cards border: Opcional, 1px rgba(255,255,255,0.12)

Text primary: rgba(255,255,255,0.87)
Text secondary: rgba(255,255,255,0.60)
```

**GRÁFICO:**

**Acessibilidade de Gráfico:**
- [ ] Não dependa apenas de cor (use padrões, marcadores)
- [ ] Labels descritivos em eixos
- [ ] Tooltip com valores exatos
- [ ] Exportável como CSV para screen readers
- [ ] Contraste de linhas/barras >3:1

**Interatividade:**
- Hover: Highlight data point + tooltip
- Click: Drill-down (se aplicável)
- Legend: Toggle series visibility

**PERFORMANCE:**

**Considerações para Dashboard:**
- WebSocket para dados real-time (evite polling)
- Virtual scrolling se muitos items (>100)
- Skeleton screens em loading states
- Otimizar re-renders (React.memo, useMemo)

**ACESSIBILIDADE:**

**Navegação por Teclado:**
```
Tab: Sidebar → Cards → Gráfico → Controles
Enter/Space: Ativa item da sidebar
Arrow keys: Navega dentro do gráfico
```

**ARIA:**
```html
<nav aria-label="Main navigation">
  <a href="/dashboard" aria-current="page">Dashboard</a>
</nav>

<section aria-label="Key metrics">
  <article aria-labelledby="revenue-label">
    <h3 id="revenue-label">Revenue</h3>
    <p aria-label="Revenue is $1,234, up 12.5% compared to last month">
      $1,234 <span>+12.5%</span>
    </p>
  </article>
</section>
```

**RECOMENDAÇÕES ESPECÍFICAS:**

**CRÍTICO:**
1. Validar contraste de cores (dark theme pode falhar WCAG)
2. Implementar keyboard navigation completo
3. Loading states para cards (skeleton screens)

**IMPORTANTE:**
4. Botão collapse/expand sidebar (ganhar ~240px)
5. Export data em CSV para acessibilidade
6. Responsividade para mobile (stack vertical)

**MELHORIAS:**
7. Drag-and-drop cards para personalização
8. Dark/light theme toggle
9. Filtros de data range acima dos cards

**PERGUNTAS DE CLARIFICAÇÃO:**
1. Dados atualizam real-time ou refresh manual?
2. Usuários podem customizar quais métricas ver?
3. Dashboard precisa ser printável/exportável?
